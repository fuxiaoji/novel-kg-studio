# DQA30 · 30 本汇总分析（前 20 冻结 + batch03 新 10）

数据源：`dqa_local_c24_pure9_consensus20`（164 题）+ `dqa30_attention/batch03_eval`（70 题），共 234 题。
**30 本合计：G5 124/234 (53.0%)，B1 尾窗 108/234 (46.2%)，绝对差 +6.8pp。**

方法对齐：C24 的 original/reversed/cyclic/c24/tail ≡ 本协议的 G1/G2/G3/G5/B1。
注意：两批 G1-G3 图谱检索为不同时期实现（早期 C24 vs 当前 attention 变体），跨批同名列仅方法规格一致，实现有差异；G4/B2/B3/Q0 仅存在于新 10 本。

## 零、方法定义（按 `scripts/run_dqa30_batch_eval.py` 实现标注）

**公共基础层**（G1–G5、B3 共用）：
- 长文切成 **1500 字符 / 100 重叠** 的 chunk（`C8Context.build`），建 BM25 索引，且每个 chunk 用 BGE-M3 编码为稠密向量。
- **按选项检索（"attention" 的由来）**：每题对每个选项单独构造查询 `"Question: <题面>\nCandidate answer: <该选项>"`，用 BGE-M3 编码得到该选项自己的查询向量（`query_vectors[qi]`）。每个选项各"注意"一遍文本与图谱。
- 答题统一走 `call_json`：最多 2 次尝试，`selected_letter` 必须在 A/B/C/D 内，否则记 invalid；prompt 强调"逐选项当作命题评估、检索≠证明、优先最终揭示而非早期假设/误导、缺失证据=未知而非反驳、按事件语义消解译名别名、遵守 NOT/EXCEPT"。单模型 **qwen3.5:9b**，think off，`num_ctx=16384`。

| 方法 | 实现 |
|---|---|
| **G1** 原序图谱 | 选项按 **`[0,1,2,3]`** 原序展示。`answer_evidence(..., include_graph=True)`：对每个选项做**双通道文本召回**（BM25 top36 + 稠密 top80，RRF 融合 `1/(40+r)` + `1.2/(40+r)`，去相邻重复后取 top5 chunk）**再加图谱通道**（`_option_packet`：用 personal-rank 给图上节点按"题目+该选项"打分，边按关系类型加权——`supports/contradicts/motive/means/opportunity/witnessed_by/belongs_to/temporal_sequence` ×1.8，`related_to/mentions/located_at/appears_at` ×0.2，其余 ×0.8——再乘置信度×两端节点分，把边质量聚合到其关联 chunk，取图 top40；三路 RRF `BM25:1.0 / dense:1.2 / graph:1.5` 各除以 `40+rank`，多样性挑选 top5）。4 个选项的文本包按 best_rank 合并去重成 **OPTION-CONDITIONED ORIGINAL PASSAGES**，图谱边抽前 2 条/选项格式化为 **HIGH-VALUE GRAPH RELATIONS（supplement only，原文优先）**。选项即原序，结果无需映射。`max_tokens=220`。 |
| **G2** 逆序图谱 | 与 G1 同流程，仅选项展示顺序为 **`[3,2,1,0]`**。模型按显示顺序输出，`map_to_original` 映射回原始标签（`LETTERS[order[LETTERS.index(letter)]]`）。 |
| **G3** 循环图谱 | 与 G1 同流程，仅选项展示顺序为 **`[1,2,3,0]`**，同样映射回原始标签。 |
| **G4** 原逆一致门控 | **不独立检索**。`G4 = (G1 == G2 且两者合法) ? G1 : B1尾窗`。记录 route `graph_stable` / `tail_fallback`。检验"选项顺序扰动下答案是否稳定"。 |
| **G5** 三排列多数 | **不独立检索**。统计 G1/G2/G3 映射回原标签后的三个字母，任一字母 **≥2 票** → 取多数（`graph_majority`）；否则回落到 **B1 尾窗答案**（`tail_fallback`）。C24 一致性对照。 |
| **B1** 尾窗 50k | 直接取全文 **最后 50,000 字符**作唯一上下文（`answer_tail`，`max_tokens=120`）。无检索、无图谱。 |
| **B2** 全量压缩 | 每个 novel 预压缩一次（与题目无关）：L1 按 **6000 字符/100 重叠**切块逐块压缩成事实摘要（保留人名/地点/时间/行动/陈述/线索/可疑细节、丢弃文学描写，`max_tokens=2500`）；合并后若超 **40,000 字符**上限再做 L2 二次压缩（`max_tokens=2000`），结果缓存于 `compression/<novel>/compressed.json`。答题时压缩文本作唯一上下文（`answer_compressed`，`max_tokens=160`）。 |
| **B3** BGE-M3 + BM25 RRF | 与 G 系列同一套 C8 检索，但 **`include_graph=False`** → 只走 `option_text_packet` 的文本双路 RRF，**不加任何图谱链接**，prompt 无 HIGH-VALUE GRAPH RELATIONS 段，选项用原始顺序。纯文本 RAG 对照。 |
| **Q0** 仅题目 | 只给题目+选项，**无任何小说上下文**（`answer_question_only`，`max_tokens=80`）。作难度探测：Q0 答错的题归入"困难子集"。 |

**图谱检索 G1–G3 三者唯一差别 = 选项展示顺序（选项与字母标签的对应关系被置换）；检索与推理逻辑完全一致**，G4/G5 只是对三种排列的输出做后处理（门控 / 多数），本身不再调用模型。
